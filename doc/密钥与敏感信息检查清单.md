# 密钥与敏感信息检查清单

提交前逐项看。本地开发口令已经写在 `docker-compose.yml` 和 `application.yml` 里，那是仓库约定的开发默认值，不要再复制到新文件，也不要拿到生产环境用。

## 必须被忽略、不能进提交

对照根目录 `.gitignore`：

| 路径 | 原因 |
|---|---|
| `backend/src/main/resources/jwt/private.pem` | RS256 签发私钥。`JwtService` 用 PKCS#8 PEM。泄漏等于可以伪造 Access Token |
| `*.pem`（另有否定规则） | 公钥 `public.pem` 同样不入库。例外只有 `*.pem.example` 与 `backend/src/main/resources/jwt/public.pem.example` |
| `application-local.yml` | M00 约定的本机覆盖（数据源、Redis 等）。可以创建，不要提交 |
| `.env`、`.env.*` | 生产口令。只保留并提交 `.env.example`（占位符，不是真密码） |
| `logs/`、`*.log` | 本地验证码会打到日志：`[邮箱验证码·本地模拟] … 验证码=` |
| `e2e/.seed.json` | E2E 落盘的账号与口令 |
| `e2e/loadtest/*.jtl`、`jmeter.log`、`report-mode*/` | 压测产物，可能含 token 或用户名 |

生成密钥（成对，不要只拷 `public.pem.example`）：

```bash
mkdir -p backend/src/main/resources/jwt
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 \
  -out backend/src/main/resources/jwt/private.pem
openssl rsa -pubout \
  -in backend/src/main/resources/jwt/private.pem \
  -out backend/src/main/resources/jwt/public.pem
```

`git status` 里不应出现 `private.pem` / `public.pem`。

## 提交前命令

在仓库根目录：

```bash
git status --short
git check-ignore -v backend/src/main/resources/jwt/private.pem .env application-local.yml || true
git diff --cached --stat
```

缓存区里若出现 `.pem`、`.env`（且不是 `.env.example`）、`application-local.yml`，先 `git restore --staged` 再确认忽略规则，不要用 `git add -f`。

搜一下即将提交的 diff，不应新增：

- PEM 私钥块（文件头含 `PRIVATE KEY`）
- 真实的 `DB_PASSWORD`、`SUPER_ADMIN_PASSWORD`（`.env.example` 里的 `ChangeMe_…` 占位可以）
- 邮件 SMTP 口令、云厂商 AK/SK、RocketMQ ACL（本地 `application.yml` 的 access-key/secret-key 是空字符串）

## 仓库里已有、但仍要当开发机密对待

这些文件已被跟踪，改动时不要把生产值写进去：

- `docker-compose.yml`：MySQL root `123456`，Redis 无密码，Grafana `admin/admin`。只用于本机端口 33061 / 16379 / 3000。
- `application.yml`：`flashticket.bootstrap.super-admin.password` 默认 `SuperAdmin@2026`，注释写明勿用于生产。生产走 `application-prod.yml` 的 `${SUPER_ADMIN_PASSWORD}`，由 `.env` 注入，库中已有超管时引导会跳过。
- `application-prod.yml`：数据源密码是 `${DB_PASSWORD}`，没有默认口令。JWT 仍指向 classpath PEM；上生产应改为环境注入的密钥，不要把生产私钥提交进 `resources/jwt/`。

## 运行时不要扩散的数据

- Access Token 放 `Authorization: Bearer`，不要写进 URL、截图、Grafana 标注或文档。
- Refresh Token 在 HttpOnly Cookie（`ft_refresh_token` / `ft_admin_refresh_token`），接口 JSON 不返回它。
- 验证码只在 local 打日志。生产不能用 `LogVerificationCodeSender`。
- 通知正文不要带 JWT、验证码或支付敏感字段（设计约束见通知模块文档）。
