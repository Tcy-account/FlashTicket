技术选型定稿
2026 年 10 月 11 日

我们不再逐项确认，剩余技术全部采用我推荐的方案。
FlashTicket 最终定位为：
基于 Java 21 + Spring Boot 3.5 + Vue 3 的高并发票务抢购与交易平台，采用模块化单体架构，重点解决库存超卖、异步削峰、消息可靠性、订单一致性和高并发性能问题。
项目只包含普通 Java 业务系统，不引入 AI Agent、微服务或其他与目标无关的技术。

日志和追踪统一携带 traceId、spanId，业务侧额外记录 requestId、orderNo 等关联字段。注意不要将密码、Token、支付敏感数据直接写入日志。
开发阶段只启用控制台日志、Actuator 和 Prometheus；Loki、Tempo、Alloy 在性能优化阶段加入，避免一开始运行过多容器。
6. 测试与压测
分类	最终技术	目的
单元测试	JUnit 5	业务规则
模拟依赖	Mockito	隔离外部依赖
断言	AssertJ	可读性更好的测试
Spring 集成测试	Spring Boot Test	Controller、Service、事务
容器化集成测试	Testcontainers	MySQL、Redis、RocketMQ
接口测试	REST Assured	API 自动化
并发压测	JMeter	抢票高并发与吞吐量
前端单测	Vitest	Vue 组件和逻辑
前端 E2E	Playwright	完整购票流程
静态代码检查	Checkstyle + SpotBugs	代码质量
JVM 性能分析	JFR	分析热点和锁竞争
不选择 JMeter 和 Gatling 同时作为主要压测工具，避免重复建设。使用 JMeter 作为统一压测基准。
必须验证的指标包括：
- 接口 QPS、P95、P99、错误率。
- 最终成功创建订单的速率。
- 数据库库存是否超卖。
- RocketMQ 消息消费延迟和积压量。
- MySQL 锁等待与连接池状态。
- Redis 和 JVM 资源使用情况。
- 故障恢复后是否出现重复订单和库存泄漏。

原因不是这些技术没有价值，而是当前项目最重要的是交易正确性、高并发和可复现测试。
