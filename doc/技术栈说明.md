# FlashTicket 技术栈说明

版本以仓库锁定为准：`backend/pom.xml`、`docker-compose.yml`、`package.json`、`README.md`。这是**演出抢票与票务订单**后端，加上用户端/管理端两个前端。支付是进程内 `MOCK_WALLET`，票是数量型票档（不选座）。不要把它讲成完整商城或已上线的支付系统。

## 后端与数据

| 项 | 锁定 | 在项目里做什么 |
|---|---|---|
| Java | 21（`pom.xml` `java.version`） | 语言基线。M17-02 压测报告写的运行时是 Java 24，那是那次压测机器，工程目标仍是 21 |
| Spring Boot | 3.5.6 | Web、Security、Validation、调度、Actuator |
| MyBatis-Plus | 3.5.12 | 单表 CRUD。库存、订单状态、Outbox 租约用注解里的手写 SQL，不用 `@Version` 插件 |
| MySQL | 镜像 `mysql:8.4`，宿主 `33061` | 权威账本。库名 `flashticket`，`utf8mb4`，会话时区 UTC。本地 root 口令见 `docker-compose.yml`（仅开发） |
| Redis | 镜像 `redis:7.4`，宿主 `16379`，本地无密码 | Refresh 会话、验证码、滑动窗口限流、可选库存准入快照 |
| RocketMQ | 镜像 `apache/rocketmq:5.3.0`；客户端 `rocketmq-v5-client-spring-boot-starter` 2.3.6 | namesrv `9876`、broker `10911`、proxy gRPC `8081` / HTTP `18080`。Topic：`ft-purchase`、`ft-order-close`、`ft-notification` |
| Flyway | `flyway-core` + `flyway-mysql`（随 Boot 3.5.6） | `V1`～`V17`，`baseline-on-migrate: false` |
| 安全 | Spring Security 6 + jjwt，RS256 | Access Token 默认 15 分钟；Refresh 走 HttpOnly Cookie，不进 JSON |
| 可观测 | Actuator + `micrometer-registry-prometheus` | `/actuator/prometheus`。生产 profile 默认不暴露该端点 |

连接默认值在 `backend/src/main/resources/application.yml`：JDBC `127.0.0.1:33061`，Redis `127.0.0.1:16379`，RocketMQ `localhost:8081`。容器内生产覆盖见 `application-prod.yml`（主机名 `mysql` / `redis` / `proxy`）。

## 前端与工程

| 项 | 锁定 | 说明 |
|---|---|---|
| 用户端 | Vue 3 + TypeScript + Vite + Naive UI + Tailwind + Pinia | `apps/ticket-web`，开发端口 5173 |
| 管理端 | Vue 3 + TypeScript + Vite + Element Plus + SCSS + Pinia | `apps/admin-web`，开发端口 5174 |
| 共享包 | `packages/shared-types`、`api-client`、`shared-utils` | pnpm workspace（`pnpm-workspace.yaml`） |
| 包管理 | pnpm（`package.json` `packageManager`） | 根脚本 `pnpm dev` 并行起两个前端。Vite 把 `/api`、`/actuator` 代理到 `localhost:8080` |
| 容器编排 | Docker Compose，`name: flashticket` | 本地中间件 + Prometheus + Grafana。生产参考 `docker-compose.prod.yml` 与 `doc/生产部署手册-1Panel.md` |
| 监控 | Prometheus `v2.55.1` :9090；Grafana `11.4.0` :3000 | 预置看板「FlashTicket 运营监控」，`admin/admin` |
| E2E | Playwright（`e2e/`，独立 npm，不进 pnpm workspace） | `e2e/tests/smoke.spec.ts`：注册→登录→抢票→支付→门票→退款 |
| 压测 | JMeter（`e2e/loadtest/checkout.jmx`） | 报告在 `doc/M17-02-压测报告.md`，工具版本该报告写的是 5.6.3。JMeter 本体不入库（`.gitignore` 排除 `tools/apache-jmeter-*`） |

## 明确不在本仓库范围内

- 真实支付渠道、清结算、对公账户。支付确认是同一本地事务里的模拟成功。
- 选座、实名观演人校验的完整产品（有权益表 `ft_ticket_entitlement`，演示看「支付后发出门票」即可）。
- 通用商品、购物车、多商户商城。
- 微服务拆分。可靠性靠 Outbox/Inbox 和条件更新，不靠跨服务分布式事务。

接口面以 `doc/M17-05-API清单.md` 为准（该文档写明 16 个域、31 个 Controller、约 90 个端点）。
