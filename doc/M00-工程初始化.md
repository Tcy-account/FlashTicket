- 阶段编号：M00
- 所属里程碑：A · 账户基础（M00–M03）
- 任务定位：工程初始化，后端与双前端能够启动、互通
- 依据文档：《FlashTicket 全项目开发计划》《前端页面设计规范》《跨域一致性与工程落地审查》
- 交付日期：2026-10-12

## 一、目标与范围

M00 是 FlashTicket 的第一个开发阶段，核心交付是「后端和双前端能够启动、互通」。

验收标准一句话：**能在浏览器发出真实后端请求，并正确显示成功、失败和服务不可用状态。**

### 范围边界

- 后端：Java 21 + Spring Boot 3.5 单 Maven 工程，搭建基础包结构、中间件连通、统一响应与异常、Spring Security 基础、Flyway 接入、健康检查与基础集成测试。
- 前端：初始化 ticket-web、admin-web，完成全局视觉 Token、布局、Axios/Pinia/Vue Router、登录注册视觉页面、开发专用 API Lab、前端代理与服务连接检测。
- **不建任何业务表**：遵循「规则三 · Flyway 跟随业务开发」，M00 只创建当前功能需要的数据库对象（即空基线迁移），`ft_user` 等业务表从 M01 起逐阶段追加迁移。

## 三、API 契约

### 3.1 统一响应信封 ApiResponse\<T\>

所有接口（含错误）统一套用以下信封，前端 Axios 统一解析。

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": { },
  "requestId": "req_01J9X8K3W2",
  "traceId": "01J9X8K3W2A1B2C3D4",
  "timestamp": "2026-10-12T06:00:00.123Z"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| code | string | 业务码，大写语义码（`SUCCESS` 或具体错误码），非 HTTP 状态码 |
| message | string | 人可读提示，简体中文；失败时对用户安全，不泄露堆栈、内部结构、账号是否存在 |
| data | object/null | 业务数据；列表接口统一 `{ items, total, page, pageSize }` |
| requestId | string | 本次请求业务号，用于幂等追踪与对账 |
| traceId | string | 链路追踪 ID，仅可观测用途，不可当幂等键（重试会产生新 Trace） |
| timestamp | string | ISO-8601 UTC 时间戳 |

> HTTP 状态码与业务码分离：HTTP 码管传输语义（2xx/4xx/5xx），`code` 管业务语义。前端「服务不可用」看 5xx，「业务失败」看 4xx + code，「成功」看 `code == SUCCESS`。

### 3.2 通用错误码

| code | HTTP | 语义 | M00 阶段是否已覆盖 |
|---|---|---|---|
| SUCCESS | 200 | 成功 | 是 |
| PARAM_ERROR | 400 | 参数校验失败 | 是 |
| UNAUTHORIZED | 401 | 未认证 / 凭据无效 | 预留（M02 起用） |
| FORBIDDEN | 403 | 已认证但无权限 | 预留（M03 起用） |
| NOT_FOUND | 404 | 资源不存在 | 是 |
| CONFLICT | 409 | 状态 / 唯一性冲突 | 预留（M01 起用） |
| TOO_MANY_REQUESTS | 429 | 触发限流 | 预留（M15 起用） |
| INTERNAL_ERROR | 500 | 系统内部错误，不返回堆栈 | 是 |
| SERVICE_UNAVAILABLE | 503 | 依赖不可用（DB / Redis） | 是 |

业务码命名约定（后续模块遵守）：`{域}_{含义}` 大写，如 `AUTH_EMAIL_SENT_LIMIT`、`INVENTORY_SOLD_OUT`、`ORDER_ALREADY_PAID`。

### 3.3 健康检查接口

| 方法 | 路径 | 作用 | 返回 |
|---|---|---|---|
| GET | `/api/v1/health` | 存活探针（liveness） | `{ code, data: { status: "UP", version } }` |
| GET | `/api/v1/health/readiness` | 就绪探针：DB `SELECT 1` + Redis `PING` | 正常 `status: UP`；异常 503 + `SERVICE_UNAVAILABLE` |
| GET | `/actuator/health` | Actuator 聚合健康（含 db/redis 指示器） | 标准 Actuator 结构 |

> 业务路径统一 `/api/v1` 前缀；管理端后续走 `/api/v1/admin` 子路径（M03 起）。M00 只放健康检查，注册/登录等业务接口（如 `POST /api/v1/auth/register`）从 M01 起增量加。

### 3.4 全局异常处理映射

| 异常类型 | 映射 |
|---|---|
| `MethodArgumentNotValidException` / `ConstraintViolationException` | 400 + `PARAM_ERROR`，message 取第一条校验信息 |
| 自定义 `BizException(code, message)` | 按 code 映射 4xx/409，业务码透传 |
| `AccessDeniedException` / `AuthenticationException` | 403 `FORBIDDEN` / 401 `UNAUTHORIZED` |
| `DataAccessException` / 其余 `Exception` | 500 `INTERNAL_ERROR`，日志记堆栈、响应脱敏 |

配套要求：响应头透出 `X-Request-Id` 与 traceId；`requestId`/`traceId` 由过滤器统一生成注入 MDC；日志不落密码、Token、验证码。
